3. Step-by-Step Data Workflow

  1. PDF Upload & Caching: User uploads PDFs in the sidebar. File signatures (name, size) are checked to prevent redundant re-indexing on UI reruns.
  2. Parsing & Metadata: PyPDFLoader extracts text page-by-page, attaching metadata (source_name and page).
  3. Semantic Splitting: RecursiveCharacterTextSplitter creates 800-character chunks with 100-character overlap to preserve boundary context.
  4. Vector Embedding: nomic-embed-text converts chunks into 768-dimensional dense vectors.
  5. FAISS Indexing: Vectors are stored in an in-memory index for millisecond similarity retrieval.
  6. History-Aware Query Reformulation: When follow-up questions are asked, LangChain's contextualizer converts pronouns into a standalone search query.
  7. Grounded Response Generation: Top-K chunks are injected into a strict system prompt and streamed token-by-token via Streamlit.

5. Top 25 Viva / Technical Interview Questions & Answers

Q1: What is Retrieval-Augmented Generation (RAG) and why is it used over Fine-Tuning?

Ans: RAG retrieves relevant document chunks from a vector database and injects them into the prompt of a frozen LLM at inference time. Unlike fine-tuning, RAG eliminates the risk of catastrophic forgetting, allows instant document updates without retraining, guarantees verifiable source citations, and costs zero training compute.

Q2: Why use Ollama and local models instead of OpenAI/Cloud APIs?

Ans: Local execution guarantees 100% data privacy (crucial for confidential medical, legal, and financial PDFs), eliminates recurring API token costs, and enables offline operation with zero internet dependency.

Q3: What is the purpose of text chunking (chunk_size=800, chunk_overlap=100)?

Ans: Embedding an entire 50-page document into a single vector averages out and loses fine-grained semantic detail. Chunking divides text into coherent paragraphs. The 100-character overlap prevents sentences and critical facts from being split across chunk boundaries.

Q4: How does FAISS work and what distance metric does it use?

Ans: FAISS (Facebook AI Similarity Search) is an optimized in-memory vector index that computes high-dimensional vector distances (Cosine Similarity / Euclidean L2 distance) to find the nearest document chunks to a user's query vector in milliseconds.

Q5: What is the difference between `nomic-embed-text` and `llama3`?

Ans: nomic-embed-text is a dedicated text embedding model that maps sentences into 768-dimensional coordinates. llama3 is a generative autoregressive language model that reads the retrieved context and writes natural language answers.

Q6: How does Multi-Turn Conversational Memory work in your project?

Ans: We use LangChain's create_history_aware_retriever. When a user asks a follow-up query (e.g. "What were his 3 main findings?"), an LLM sub-chain evaluates the past chat history and reformulates the prompt into a standalone search query before querying FAISS.

Q7: What is LangChain LCEL?

Ans: LangChain Expression Language (LCEL) is a declarative, composable framework in LangChain 0.2+ that allows developers to assemble prompts, retrievers, and LLMs into production-ready chains with out-of-the-box streaming and batching support.

Q8: How do you prevent LLM hallucinations?

Ans: 1) Setting temperature to 0.0 for deterministic outputs; 2) Enforcing strict system prompt constraints (instructing the model to state "I don't know" if the answer is absent from context); 3) Displaying exact source page numbers and text snippets for verification.

Q9: How does real-time token streaming work in Streamlit?

Ans: rag_chain.stream() yields output tokens as a generator. Streamlit's st.write_stream() consumes this generator to display characters progressively with a typewriter effect, improving user experience by eliminating waiting time.

Q10: Why is ingestion caching implemented?

Ans: Streamlit re-executes the entire script whenever a user interacts with widgets. Ingestion caching stores a hash signature (filename, filesize) in st.session_state, preventing redundant and CPU-intensive re-embedding during chat conversations.

Q11: What is the role of `pypdf`?

Ans: pypdf is the underlying PDF parser used by PyPDFLoader to parse raw PDF streams, extract textual contents, and preserve page indices for metadata tracking.

Q12: What is Top-K retrieval and how does changing it affect performance?

Ans: Top-K controls how many relevant chunks are fetched from FAISS. If Top-K is too low (e.g., 1), necessary context may be omitted; if Top-K is too high (e.g., 10), irrelevant context can confuse the LLM and slow down inference.

Q13: What is the temperature parameter in LLMs?

Ans: Temperature scales the probability distribution (softmax logits) of next-token predictions. A temperature of 0.0 ensures greedy, factual decoding, while higher values (e.g. 0.8) introduce randomness.

Q14: How are 1-indexed page numbers displayed?

Ans: PDF libraries use 0-indexed page numbers (page 0 is page 1). In app.py, we add +1 to metadata["page"] before displaying citation cards in the UI.

Q15: What happens if a scanned image PDF is uploaded?

Ans: Text extraction returns empty because standard PDF parsers only extract digital text layers. An OCR engine (e.g., Tesseract, EasyOCR) is required to extract text from scanned images.

Q16: How does the app auto-detect installed Ollama models?

Ans: get_installed_ollama_models() sends an HTTP GET request to Ollama's local REST endpoint http://localhost:11434/api/tags and parses available model names dynamically into the UI dropdown.

Q17: What is the "Stuff Documents" strategy in LangChain?

Ans: It concatenates all retrieved document chunks into a single context string that fits directly into the prompt template for the LLM.

Q18: How does this project handle multiple PDF files simultaneously?

Ans: process_pdfs_to_vector_db() loops through all uploaded file paths, extracts chunks, stamps each chunk with source_name, and combines them all into a unified FAISS index.

Q19: How can this system be scaled for enterprise use?

Ans: By replacing in-memory FAISS with a persistent distributed vector database (e.g., Qdrant, Milvus, ChromaDB, or Pgvector) and implementing asynchronous background ingestion queues with Redis/Celery.

Q20: What is Hybrid Search?

Ans: A technique combining dense semantic vector search (embeddings) with sparse keyword search (BM25) to catch both high-level semantic intent and exact keyword matches (e.g. product IDs, legal clauses).

Q21: Can this application run completely offline?

Ans: Yes. Once the Python dependencies and local Ollama model weights are installed, no network connection is needed.

Q22: What are the primary hardware requirements?

Ans: Minimum 8GB RAM (16GB recommended), multi-core CPU or NVIDIA GPU with 4GB+ VRAM, and ~5GB disk space for model weights.

Q23: What is `MessagesPlaceholder` in LangChain?

Ans: It is a prompt template element that dynamically injects the list of past message objects (HumanMessage and AIMessage) into the conversation history slot of the prompt.

Q24: What are the main limitations of this project?

Ans: 1) Requires consumer GPU/RAM for fast local inference; 2) Does not natively parse non-text scanned image PDFs without OCR; 3) FAISS index is in-memory per session.

Q25: What are the real-world applications of this project?

Ans: Confidential legal case review, medical diagnostic report lookup, financial audit document exploration, enterprise HR policy assistants, and academic research analysis.
